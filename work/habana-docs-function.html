Habana Labs (Intel)

Building a Documentation Function From Zero

Building the documentation infrastructure, processes, content architecture, and team for a growing AI software platform.

Role
Senior Technical Writer / Team Lead
Focus
Documentation Strategy · Infrastructure · Docs-as-Code · Information Architecture · Engineering Contribution

Context

I joined Habana Labs as its first technical writer while the company was building and scaling its AI software platform.

Documentation existed, but there was not yet a mature documentation function or scalable infrastructure. As the platform and engineering organization grew, documentation needed to evolve from individually produced files into a structured system supporting frequent software releases, increasingly complex technical content, engineering collaboration, and a growing user base.

The Challenge

The challenge was to establish a documentation system that could scale with a rapidly evolving AI software platform.

  • Move away from document-centric Word-based authoring.
  • Establish source-controlled documentation workflows.
  • Select and implement appropriate documentation tooling.
  • Create scalable information architecture, standards, and review processes.
  • Support frequent software releases.
  • Create ways for engineers and technical contributors to participate.
  • Cover complex workflows spanning installation, configuration, APIs, AI frameworks, containers, orchestration, distributed workloads, debugging, and optimization.
  • Grow documentation capacity beyond a single technical writer.

My Role

As the first technical writer, I was responsible for establishing the documentation function while also owning documentation delivery for the platform.

  • Assessed the existing environment and identified infrastructure and process gaps.
  • Evaluated and implemented a docs-as-code approach.
  • Migrated documentation from Word-based authoring to Sphinx and Read the Docs.
  • Established source-controlled authoring and publishing workflows.
  • Restructured information architecture around user workflows.
  • Established standards, reviews, and release processes.
  • Partnered with R&D, Product Management, Application Engineering, and Marketing.
  • Created contributor workflows and trained engineers and technical contributors.
  • Recruited and trained two additional technical writers.
  • Managed documentation delivery alongside a six-week software release cadence.

Approach

01

Build the Documentation Infrastructure

I evaluated tooling and moved the organization from Word-based documentation toward a docs-as-code model using Sphinx and Read the Docs. The new model introduced source control, structured text-based authoring, repeatable publishing, and a foundation that could support contributions from more than one author.

The objective was not simply to replace one authoring tool with another. It was to establish documentation as a maintainable technical system.

02

Restructure Around User Workflows

I reworked the information architecture around the tasks users needed to accomplish across software installation and configuration, APIs, PyTorch training and inference, Docker and Kubernetes environments, distributed workloads, debugging, performance optimization, and developer workflows.

This created a more coherent experience across software, hardware, APIs, orchestration, and AI development.

03

Establish Contribution and Governance

Scaling documentation required reducing dependency on a single owner while maintaining quality and consistency. I established standards, authoring guidance, review processes, contributor workflows, and training for engineers and technical contributors.

Engineering / Technical Contributors → Documentation Workflow → Review → Published Documentation
04

Scale the Documentation Function

I recruited and trained two additional technical writers and established processes that allowed documentation work to be distributed while maintaining common standards and release expectations. Delivery was coordinated with a six-week software release cadence and required ongoing collaboration across technical and product teams.

What Changed

  • Documentation moved from Word-based authoring to Sphinx and Read the Docs.
  • Documentation became source controlled with repeatable publishing workflows.
  • Information architecture was reorganized around technical user workflows.
  • Standards and review processes were established.
  • Engineers and technical contributors gained structured contribution paths.
  • Documentation delivery became integrated with the software release cadence.
  • The documentation team expanded from the first technical writer to a multi-writer function.
