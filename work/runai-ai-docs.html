NVIDIA / Run:ai

AI-Ready Documentation & Agent Workflows

Designing documentation systems and contribution workflows that enable AI agents to work effectively while preserving technical accuracy, standards, and human review.

Role
Technical Marketing Engineer / Documentation Lead
Focus
AI-Ready Documentation · Agent Workflows · Agent Skills · MCP · Developer Experience · Governance

Context

As AI-assisted development became part of the Run:ai developer experience, documentation needed to support more than human readers and traditional authoring workflows.

AI agents could consume technical documentation, interact with product capabilities, and help engineers create or update documentation. But giving an agent access to a repository was not enough. Effective contribution required explicit context, reusable instructions, controlled terminology, contribution standards, and review mechanisms.

At the same time, Run:ai was developing an MCP server that exposed product capabilities to AI clients and agents, creating another intersection between APIs, documentation, developer experience, and AI-assisted workflows.

The Challenge

How can AI agents participate in technical documentation and developer workflows without sacrificing accuracy, consistency, ownership, and human oversight?

  • Documentation standards often existed as knowledge held by the documentation owner rather than instructions an agent could reliably follow.
  • AI-generated documentation could appear plausible while using incorrect terminology, assumptions, or product behavior.
  • Engineers and external contributors needed repeatable AI-assisted workflows rather than individually invented prompting.
  • Documentation needed to be discoverable and consumable by AI systems.
  • Product capabilities exposed through MCP needed to reflect actual supported API behavior.
  • AI-assisted contribution still required human review and governance.

My Role

My role spanned both the documentation system and the emerging AI developer experience. I worked on transforming documentation standards and contribution knowledge into reusable Agent Skills, while also participating from the early stages of the Run:ai MCP server alongside Engineering and Product.

  • Designed an agent-assisted documentation contribution model.
  • Translated standards, terminology, and workflows into reusable Agent Skills.
  • Defined how agents should approach documentation tasks rather than relying only on generic prompting.
  • Reviewed how documentation should be structured and exposed for AI consumption.
  • Worked with Engineering and Product on MCP-supported API operations and use cases.
  • Validated whether API operations exposed through MCP behaved as expected.
  • Identified inaccuracies, unsupported assumptions, and gaps during development and review.
  • Acted as a primary reviewer of the MCP developer and documentation experience alongside Engineering and Product.

Approach

01

Make Documentation Knowledge Explicit

For an AI agent to participate reliably, terminology decisions, content structures, repository conventions, contribution workflows, and review expectations need to become explicit and reusable. I worked on structuring this guidance so an agent could understand controlled terminology, documentation expectations, repository conventions, and task-specific procedures.

02

Encode Reusable Workflows With Agent Skills

I introduced Agent Skills into the documentation workflow as reusable instructions for AI agents performing documentation tasks. The skills encode how a Run:ai documentation expert approaches a task while keeping resulting changes inside the normal repository and review workflow.

Contributor / Engineer → AI Agent → Agent Skill → Documentation Change → Human Review
03

Support AI Consumption of Documentation

The documentation environment was designed to support AI-accessible documentation through clean Markdown representations, a documentation index for discovery, MCP-based access for compatible clients, and structured content that provides clearer context to agents and language models.

┌→ Human users Authoritative Docs ──┼→ Developers └→ AI clients / agents

The objective was not a separate documentation set for AI, but one authoritative environment usable by humans and AI systems.

04

Validate the MCP Developer Experience

My involvement with MCP began during development rather than after the product was complete. I worked with Engineering and Product to review supported Run:ai API operations, understand intended use cases, validate behavior, identify inaccurate or unsupported scenarios, surface documentation and product gaps, and review terminology and developer-facing explanations.

What Changed

  • Documentation standards and workflows could be expressed as reusable instructions for AI agents.
  • Agent Skills provided a repeatable mechanism for agent-assisted contribution.
  • Engineers and contributors could use AI assistance within established Git and review workflows.
  • Documentation became easier for AI clients and agents to discover and consume.
  • MCP capabilities were reviewed against actual API behavior and intended use cases as the developer experience matured.
  • Human review, technical validation, and governance remained part of the contribution model.

AI should not remove documentation governance.

The goal is a system where AI can participate effectively while accuracy, consistency, ownership, and human oversight remain controlled.
