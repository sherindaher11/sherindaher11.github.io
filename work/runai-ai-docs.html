NVIDIA / Run:ai

AI-Ready Documentation & Agent Workflows

Designing documentation systems and contribution workflows that enable AI agents to participate effectively while preserving technical accuracy, standards, and human review.

Role
Technical Marketing Engineer / Documentation Lead
Focus
AI-Ready Documentation · Agent Workflows · Agent Skills · MCP · Developer Experience · Governance

Context

As AI-assisted development became part of the Run:ai developer experience, documentation needed to support more than human readers and traditional authoring workflows.

AI agents could consume technical documentation and help engineers create or update it, but repository access alone was not enough. Reliable contribution required explicit context, reusable instructions, controlled terminology, contribution standards, and review mechanisms.

At the same time, Run:ai was developing an MCP server that exposed product capabilities to AI clients and agents, creating another intersection between APIs, documentation, developer experience, and AI-assisted workflows.

The Challenge

How can AI participate in technical documentation and developer workflows without sacrificing accuracy, consistency, ownership, and human oversight?

  • Documentation standards often existed as expert knowledge rather than instructions an agent could reliably follow.
  • AI-generated documentation could sound plausible while using incorrect terminology, assumptions, or product behavior.
  • Engineers and external contributors needed repeatable workflows rather than individually invented prompts.
  • Documentation needed to be discoverable and consumable by AI systems as well as people.
  • Product capabilities exposed through MCP needed to reflect supported API behavior.
  • AI-assisted contribution still required clear human review and governance.

My Role

My role spanned the documentation system and the emerging AI developer experience. I worked on turning documentation standards and contribution knowledge into reusable Agent Skills, while participating from the early development of the Run:ai MCP server alongside Engineering and Product.

  • Designed an agent-assisted documentation contribution model.
  • Translated documentation standards, terminology, and workflows into reusable Agent Skills.
  • Defined task-specific guidance so agents did not depend only on generic prompting.
  • Considered how documentation should be structured and exposed for AI consumption.
  • Worked with Engineering and Product on MCP-supported API operations and use cases.
  • Validated whether operations exposed through MCP behaved as expected.
  • Identified inaccuracies, unsupported assumptions, and gaps during development and review.
  • Served as a primary reviewer of the MCP developer and documentation experience alongside Engineering and Product.

Approach

01

Make Documentation Knowledge Explicit

Experienced documentation owners carry a large amount of implicit knowledge: terminology decisions, content structures, repository conventions, review expectations, and task-specific rules. For an AI agent to participate reliably, that knowledge has to become explicit and reusable.

I structured guidance around controlled terminology, documentation expectations, repository conventions, contribution workflows, review expectations, and task-specific procedures.

02

Encode Reusable Workflows With Agent Skills

I introduced Agent Skills into the documentation workflow as reusable instructions for agents performing documentation tasks. Instead of requiring every contributor to reconstruct the same prompt and context, the skill can carry the relevant workflow and standards with the repository.

Contributor / Engineer → AI Agent → Agent Skill → Documentation Change → Human Review

The model is intentionally not autonomous documentation generation. AI assistance remains inside the normal contribution and review process.

03

Make Authoritative Documentation AI-Accessible

AI readiness also changes how documentation is delivered. The environment supports AI access through clean Markdown representations of documentation pages, a documentation index for discovery, MCP access for compatible clients, and structured content that provides clearer context to agents and language models.

┌→ Human users Authoritative Docs ──┼→ Developers └→ AI clients / agents

The objective is one authoritative documentation environment that works for humans and AI systems, not separate human and machine content silos.

04

Validate the MCP Developer Experience During Development

My MCP involvement began while the product was being developed. I worked with Engineering and Product to review which Run:ai API operations should be supported, understand intended use cases, validate behavior and coverage, identify inaccurate or unsupported scenarios, surface documentation and product gaps, and review developer-facing terminology and explanations.

This put documentation and developer-experience review inside the product-development loop rather than after implementation was complete.

Outcome

The work established a foundation for AI-assisted documentation that preserves the controls required for authoritative technical content.

  • Documentation standards and workflows could be expressed as reusable instructions for AI agents.
  • Agent Skills created a repeatable mechanism for agent-assisted contribution.
  • Engineers and contributors could use AI assistance within established Git and review workflows.
  • Documentation became easier for AI clients and agents to discover and consume.
  • MCP capabilities were reviewed against actual API behavior and intended use cases as the developer experience matured.
  • Human review, technical validation, and governance remained part of the contribution model.

AI should not remove documentation governance.

The goal is a system where AI can participate effectively while accuracy, consistency, ownership, and human oversight remain controlled.
